# 第十二阶段：商品浏览量展示与有效浏览计数

## 1. 范围与当前状态

本阶段只调整商品浏览量的展示和计数规则，不改变商品、收藏、消息、预约或媒体业务。

当前本地源码、自动验证、正式云环境配置和人工真机验收均已完成：

- 已创建空 `productViews` 云数据库集合；
- 已配置 `ADMINONLY` 权限和 `idx_cleanupAfter` 非唯一升序索引；
- 已部署 `productViewAction`，并反查为 `Active / Available`；
- 已下载云端代码核对源码哈希和生产依赖；
- 已执行无写入的非法 action 安全探针，探针前后集合均为 0 条；
- 已完成多账号真机验收，浏览递增、滚动窗口、卖家排除、记录字段和原有业务回归全部通过。

详情页的浏览记录能力已在正式云环境就绪；若云函数调用失败，详情仍会安全降级，不影响商品展示。

## 2. 开发前真实现状

- 首页和搜索结果复用 `components/product-card`，原本显示 `viewCountText + 次浏览`。
- 收藏列表和“我的发布”使用各自的管理型卡片，原本分别显示浏览量。
- 用户公开主页使用独立卡片，本来只显示地点和收藏量，不显示浏览量。
- 商品详情原本显示 `X 次浏览 · Y 人关注`。
- 权威字段为 `products.viewCount`。
- `createProduct` 创建商品时把 `viewCount` 可信初始化为 `0`；发布和编辑接口均不接受客户端控制该字段。
- 工程原本没有浏览递增入口、浏览记录集合或浏览幂等机制。列表查询和详情查询都只读，不会增加计数。
- 未登录用户可以浏览公开商品详情。

因此本阶段不是修复“每次进入都加一”的既有实现，而是补齐此前缺失的有效浏览记录能力，同时避免把新计数逻辑耦合进详情查询。

## 3. 展示规则

以下列表统一隐藏浏览量，不保留空白占位：

- 首页；
- 搜索结果；
- 我的收藏；
- 用户公开主页；
- 我的发布。

“我的发布”虽然是卖家管理页，但当前卡片已经同时承载状态、时间、收藏和管理按钮。为保持最终收尾阶段的列表密度一致，本阶段不为卖家单独保留浏览统计。

商品详情继续展示浏览量，并与收藏量合并为同一条弱信息：

```text
X 人浏览 · Y 人收藏
```

零值照常显示，数据保持真实。该信息使用小字号和浅灰色，不增加图标、强调色或独立卡片。

## 4. 前端调用与失败降级

`pages/product-detail` 先通过 `ProductService` 正常加载并展示有效商品，再异步调用 `ProductViewService.recordProductView(productId)`。

调用边界：

- 仅应用内已登录用户发起浏览记录请求；匿名用户仍可正常查看详情，但本阶段不计入浏览量；
- 单个页面实例通过 `hasRecordedViewAttempt` 最多尝试一次；
- `onShow`、下拉刷新、前后台恢复和重复 `setData` 不会在同一页面实例再次调用；
- 页面重新打开后仍由服务端滚动 24 小时窗口判断；
- 计数成功时只更新当前页面中的浏览数字；
- 计数失败只在开发环境记录固定错误码，不弹窗、不阻断详情、不影响收藏、联系卖家、聊天或预约。

客户端请求只包含：

```text
action: recordView
productId
```

客户端不发送 OPENID、`viewCount`、时间窗口或浏览记录 ID。

## 5. 服务端计数与并发保证

独立云函数 `productViewAction` 从 `cloud.getWXContext()` 读取可信 OPENID，并在数据库事务内执行：

1. 读取商品并确认商品存在；
2. 确认状态属于公开详情可见的 `available`、`reserved`、`sold`；
3. 排除 `sellerOpenid` 与当前 OPENID 相同的卖家本人浏览；
4. 读取当前“用户—商品”确定性浏览记录；
5. 若 `lastCountedAt` 距服务端当前时间不足 24 小时，返回 `DUPLICATE_VIEW`；
6. 否则写入或更新浏览记录，并用 `db.command.inc(1)` 原子增加 `products.viewCount`。

确定性记录 ID：

```text
pv_ + SHA-256(productId:viewerOpenid) 的前 48 个十六进制字符
```

同一用户和商品永远竞争同一个浏览记录文档。并发请求会同时读写相同的浏览记录和商品文档，由数据库事务冲突重试、确定性 `_id` 和原子自增共同保证同一窗口最多增加一次。

正常结果原因：

```text
COUNTED
DUPLICATE_VIEW
OWNER_VIEW
PRODUCT_NOT_FOUND
PRODUCT_NOT_VIEWABLE
```

## 6. `productViews` 数据模型与云端状态

正式云环境已创建集合：

```text
productViews
```

字段：

```text
_id
productId
viewerOpenid
lastCountedAt
nextEligibleAt
cleanupAfter
createdAt
updatedAt
```

权限已配置并反查为：

```text
ADMINONLY
```

运行时只按确定性 `_id` 读写，因此除系统 `_id` 索引外不需要额外计数索引。为支持后续定期清理，云端已创建非唯一升序索引：

```text
idx_cleanupAfter
cleanupAfter ASC
```

每个“用户—商品”只保留一条记录，超过 24 小时后的有效浏览会覆盖时间字段，不会按天无限新增。`cleanupAfter` 为最近一次有效计数后的 180 天；后续部署清理任务时按该字段批量删除长期不活跃记录。当前只有清理索引，没有自动清理任务，不得宣称已自动清理。

## 8. 真机验收结果

人工多账号真机验收已全部通过：

1. 首页、搜索、收藏、公开主页和“我的发布”均不显示浏览量，卡片布局和交互正常。
2. 商品详情显示 `X 人浏览 · Y 人收藏`。
3. 买家首次进入商品详情增加 1；立即退出重进、下拉刷新、切换 Tab 和前后台恢复均不重复增加。
4. 商品卖家查看自己的商品不增加浏览量。
5. 不同买家首次查看同一商品可分别增加浏览量。
6. `productViews` 中每个“买家—商品”只有一条记录，不存在卖家本人记录。
7. `nextEligibleAt` 比 `lastCountedAt` 晚约 24 小时，`cleanupAfter` 约为最后一次有效浏览后 180 天。
8. 浏览计数调用失败时详情仍正常展示。
9. 收藏、聊天、联系卖家、预约、图片轮播、全屏预览和视频播放均无回归。
