# 第十一阶段：商品多图与演示视频

> 状态：源码、五项云函数部署、云端依赖与哈希反查、59 项自动验证及人工真机验收均已通过；本阶段正式完成。

## 1. 范围

本阶段只增强现有商品媒体能力，不改变校园线下面交定位、身份模型、商品状态机、收藏、消息或预约业务。

实现内容：

- 商品详情展示完整图片数组，并支持原生 `swiper` 左右切换；
- 图片页码、加载失败占位和从当前图片开始的全屏预览；
- 发布与编辑支持一个可选商品演示视频；
- 视频采用图片轮播下方的独立原生 `video` 卡片，避免原生视频与 `swiper` 混排的层级兼容风险；
- 列表、搜索、收藏、公开主页和“我的发布”继续只返回及加载商品封面；
- 创建、编辑和软删除把视频纳入服务端校验、幂等写入、失败回滚和云文件清理。

## 2. 根因

原发布与编辑链路已经支持最多 6 张图片：

```text
wx.chooseMedia
→ 逐张校验和上传
→ products.images
→ products.coverImage = images[0]
→ productQuery/detail
→ ProductService
```

数据库和详情接口均保留了完整 `images`，但商品详情页顶部只绑定了 `product.coverImage`，因此第二张及后续图片从未进入展示层。视频此前在选择、上传、数据模型、云端校验、编辑清理和详情播放各层均不存在。

### 2.1 后续图片预览生命周期修复

2026-07-26 的后续未提交工作树曾让商品详情 `onShow` 在每次页面再次显示时无条件调用 `loadProduct()`。系统图片预览关闭会触发 `onShow`，而 `loadProduct()` 会先清空商品并切换到 loading，因此产生整页闪动、跳顶和完整详情重查。

现已复用既有 `AppStore.productsVersion` 作为明确商品变更标记：

- `onLoad` 只执行一次首次详情加载并记录当前版本；
- 普通 `onShow`、关闭图片预览和普通前后台切换在版本未变化时直接返回；
- 商品编辑、上下架、售出、删除或预约引发的明确商品状态变化会调用 `markProductsChanged()`，详情页发现版本变化后才重新加载；
- 详情页本地收藏成功后同步已观察版本，避免随后因自己的收藏写入再次整页加载；
- 图片预览仍使用当前图片作为 `current`、有效图片数组作为 `urls`，不设置刷新标记、不导航、不重置滚动位置；
- 每页一次的浏览量尝试保护保持不变，图片预览返回不会重复增加浏览量。

该后续修复没有修改商品服务、云函数、集合、权限、索引或媒体模型；自动验证已增加生命周期边界，关闭预览后的滚动位置保持和无闪屏效果也已在第十三阶段最终真机验收中确认。

## 3. 数据模型

现有字段保持不变：

```js
{
  images: [
    "cloud://.../products/<publicUserId>/<date>/image-1.jpg",
    "cloud://.../products/<publicUserId>/<date>/image-2.jpg"
  ],
  coverImage: "cloud://.../products/<publicUserId>/<date>/image-1.jpg"
}
```

新增可选字段：

```js
{
  video: {
    fileID: "cloud://.../products/<publicUserId>/<date>/demo.mp4",
    posterFileID: "",
    duration: 12,
    width: 1080,
    height: 1920,
    size: 1234567
  }
}
```

约束：

- 图片至少 1 张、最多 6 张，单张不超过 10MB；
- 第一张图片始终是封面；
- 视频最多 1 个、最长 60 秒、不超过 50MB；
- 视频文件扩展名只接受 `mp4`、`mov`、`m4v`；
- 当前选择接口不稳定提供视频封面，因此不伪造封面；`posterFileID` 预留为空；
- 数据库只保存用户目录下的云文件 ID，不保存本地临时路径。

兼容策略：

- 不迁移、不删除、不重命名旧字段；
- 详情读取优先使用 `images`，其次兼容 `imageUrls`，最后兼容 `coverImage`、`coverUrl`、`image` 单图字段；
- 旧商品缺少 `video` 时规范化为 `null`；
- 视频字段缺失、数组化、路径或元数据异常时安全降级为无视频；
- 所有列表 DTO 不返回 `images` 或 `video`，只返回第一张封面。

## 4. 发布与编辑

发布页和编辑页共用 `ProductFormService` 的图片与视频选择、规范化和表单快照逻辑。

图片：

- 新选择追加到现有列表，不覆盖先前图片；
- 临时路径去重；
- 第一张显示“封面”标记；
- 编辑时旧云图片原样回显，只有新本地图片重新上传。

视频：

- 使用 `wx.chooseMedia({ mediaType: ['video'] })`；
- 选择后先校验类型、大小、时长和尺寸；
- 支持预览、删除后重选；
- 编辑时可保留、删除或替换旧视频。

保存：

- 图片先上传，视频后上传，最后调用创建或编辑云函数；
- 确定失败会清理本次新上传的图片和视频；
- 网络或超时导致结果未知时保留云文件 ID，并沿用原请求 ID 或 mutation ID 安全重试；
- 编辑事务成功后，服务端才清理被移除或替换的旧媒体；
- 清理失败不回滚已经成功的商品事务，继续沿用既有最终一致清理队列。

## 5. 详情页

- 图片使用独立原生 `swiper`，固定 `500rpx` 高度；
- 右下角显示 `当前序号 / 总数`；
- 图片使用 `aspectFill`，加载失败时保留区域高度并显示文字占位；
- 点击图片调用 `wx.previewImage`，预览集合只包含有效且未加载失败的图片；
- 视频位于图片轮播下方，默认不自动播放、不循环；
- 页面隐藏或卸载时通过 `wx.createVideoContext(...).pause()` 停止声音；
- 视频加载失败只降级视频卡片，不影响商品图片和文字。

## 6. 云端与权限

需部署的云函数：

```text
createProduct
manageProduct
productQuery
favoriteProduct
userQuery
```

职责变化：

- `createProduct`：保存完整图片数组和可选视频；
- `manageProduct`：所有者校验后更新视频，把旧图片、旧视频和可选视频封面加入清理列表；
- `productQuery`：列表使用封面 DTO，详情使用完整媒体 DTO；
- `favoriteProduct`、`userQuery`：列表移除完整图片数组并兼容旧封面字段。

数据库为无模式集合，本阶段不要求批量迁移或新增索引。媒体继续使用现有用户专属 `products/<publicUserId>/<date>/...` 云存储路径，因此不要求降低数据库或云存储权限。

## 9. 人工真机验收结果

2026-07-26 已完成以下人工真机验收，全部通过。测试覆盖旧商品兼容、本轮专用测试商品、多图与 MP4、页面生命周期、列表回归和云文件清理。

1. **旧单图商品**
   - 打开旧单图详情，确认图片区域正常、页码为 `1 / 1`，没有空白视频卡片；
   - 点击图片应进入全屏预览，返回后详情仍可正常操作；
   - 旧记录即使只有 `coverImage` 而没有 `images`，也应正常显示。
2. **旧多图商品**
   - 打开已含多张 `images` 的旧商品，确认图片数量、顺序和数据库一致；
   - 左右滑动到最后一张再返回，页码应同步变化；
   - 横图、竖图或加载失败时，图片区高度不应塌陷，其他商品信息不受影响。
3. **新发布 3 张图片**
   - 依次选择 3 张图片，确认追加而非覆盖，第一张显示“封面”；
   - 发布成功后打开详情，应显示 `1 / 3`，并能滑到第 2、3 张；
   - 数据库检查 `images.length === 3`、三个元素均为当前用户目录下的 `cloud://` 文件 ID，并确认 `coverImage === images[0]`；
   - 无视频时 `video` 应为 `null` 或旧数据兼容情况下不存在，不应保存本地临时路径。
4. **从第二张图片开始预览**
   - 先把轮播滑到第 2 张，再点击当前图片；
   - 全屏预览打开时当前项必须是第 2 张，随后可以前后浏览其他有效图片；
   - 关闭预览后轮播仍停留在第 2 张。
5. **新发布多图加 MP4 视频**
   - 新建测试商品，选择多张图片和一个符合限制的 MP4，确认图片与视频均有预览；
   - 发布后详情图片轮播和独立视频卡片同时存在，视频默认不自动播放、不循环；
   - 数据库确认 `video.fileID` 为当前用户 `products/<publicUserId>/<date>/...` 下的云文件 ID，`video.duration` 大于 0 且不超过 60，`video.width`、`video.height` 为正数，`video.size` 大于 0 且不超过 `52428800`；
   - 首页或列表只应请求和显示 `coverImage`，不应加载完整图片数组或视频。
6. **离开详情页后视频暂停**
   - 在详情页手动播放视频并确认有画面或声音；
   - 返回上一页、切换 Tab 或让小程序进入后台；
   - 视频必须立即暂停；重新进入详情时不得在后台继续播放。
7. **编辑增加和删除图片**
   - 编辑刚创建的测试商品，保留部分旧图、增加新图、删除一张中间旧图后保存；
   - 详情中的图片数量与顺序必须和编辑结果一致，第一张仍为封面；
   - 数据库检查 `images` 仅含最终保留和新增的云文件 ID，`coverImage === images[0]`；
   - 确认被移除且没有被其他商品引用的旧图片已从云存储删除，保留图片仍可访问。
8. **保留、替换、删除视频**
   - 不改视频保存一次，确认 `video.fileID` 和全部元数据保持不变；
   - 替换为另一个合规 MP4，确认数据库改为新 `fileID` 和新元数据，旧视频在事务成功后被清理；
   - 再编辑并删除视频，确认数据库 `video === null`，详情不再出现视频卡片，最后一个视频文件被清理；
   - 任一步失败时，不应误删当前仍被商品引用的媒体。
9. **列表封面回归**
   - 分别检查首页、搜索结果、我的收藏、卖家公开主页和“我的发布”；
   - 每处都只显示 `coverImage` 对应的第一张图片，不显示轮播或视频，不出现旧单图空白；
   - 同时回归商品状态、价格、收藏、聊天和预约入口。
10. **删除商品后的云文件清理**
    - 仅删除本轮人工创建的测试商品，确认列表和公开详情不再暴露该商品；
    - 在数据库核对软删除状态，并检查 `imageCleanupStatus` 最终为 `completed`、`imageCleanupFiles` 为空数组；
    - 在云存储逐一检查原 `images`、`video.fileID` 以及将来可能存在的 `video.posterFileID` 均已删除；
    - 若接口返回 `cleanupPending=true` 或 `cleanupFailedCount>0`，保留记录和日志，不要手工误删仍被其他商品引用的文件。

## 11. 遗留项与回滚

以下事项真实存在，但不阻塞本阶段完成：

- 商品视频暂不生成独立封面，首次播放前视觉效果依赖原生 `video`；
- 图片暂不支持手动拖拽排序；当前顺序由已有图片顺序和后续追加顺序决定，第一张始终作为封面；
- 本机 npm 11 对五个函数的生产依赖审计均报告 1 个 moderate、5 个 high 的传递依赖告警；本轮没有执行可能产生破坏性升级的 `npm audit fix --force`，应另开依赖升级任务评估。
