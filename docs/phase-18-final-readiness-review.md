## 7. 正式切换与回滚方案

推荐分阶段推进：

1. 完成用户学校补齐，并通过 Phase 22B 或明确下架/归属方案处理 20 件公开无学校业务商品；
2. 准备至少 3—5 个跨两所 active 学校的真实身份，补真实匿名/非名单、双账号并发和真机；
3. 保留单账号 canary，随后扩大固定 allowlist 并设置观察窗口；
4. 先切“全部已登录且学校有效的用户”，确认匿名产品决策后再考虑 strict-for-all；
5. 切换前后反查函数哈希、环境变量存在性、19 个索引和 `ADMINONLY` 权限，执行首页四排序、分类、搜索、分页、换校和旧 cursor 回归。

停止条件包括任何跨校泄露、strict 请求回退 legacy、游标边界失效、索引/超时/5xx 异常上升、正常学校用户出现非预期空市场、学校上下文错误或回滚演练失败。

回滚脚本已改为默认输出安全计划：显示当前配置和目标 `false/false/0`，不写数据库、不改索引/权限/环境变量，也不自动部署。真正回滚仍要求先显式补丁恢复源码配置、跑自动测试，再传 `--deploy`；部署器继续校验目标环境、HMAC、种子变量和单函数范围。
